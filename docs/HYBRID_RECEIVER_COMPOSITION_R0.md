# Tonal Hybrid Receiver Composition R0

Status: **PROPOSED / NOT PINNED / NOT SUPPORTED**

## What Tonal coordinates

Tonal does not own receiver semantics or swarm behavior. It coordinates an exact tested composition of independently versioned Tlaloc and Origami revisions.

For this proposal:

```text
TLALOC
swarm/Tlaloque search
  -> receiver candidate
  -> prompt + BOOT/Rosetta strategy + MicroAgent IR
  -> tournament/evidence
             |
             v
ORIGAMI
semantic validation
  -> self-boot carrier contract
  -> deterministic execution
  -> receiver artifact registry
             |
             v
TONAL
exact commit pins
  -> cross-component gates
  -> compatibility state
```

## Primary runtime mode

Hybrid is the primary target:

```text
model perception
  -> BOOT discovery
  -> carrier-local ROSETTA interpretation
  -> high-level navigation
Origami runtime
  -> deterministic micro-agent operations
  -> addressing / selective unfolding / computation / verification
model
  -> compact retained state
  -> next bounded access or answer
```

Native and Computational remain diagnostic baselines and must not be confused with the final Hybrid claim.

## Promotion order

1. Origami branch proves deterministic receiver contract, symbol permutation and isolation locally.
2. Tlaloc branch proves deterministic distillation and tournament hard gates locally.
3. Origami creates a synthetic self-boot carrier and Hybrid packet.
4. Tlaloc/model-facing campaign evaluates candidate receiver behavior on held-out synthetic tasks.
5. Repeat with carrier-local symbol permutations using the same external Master Prompt.
6. Repeat on more than one target model/profile where practical.
7. Origami records the winning receiver as `PROMOTED` only if its own semantic/evidence gates pass.
8. Merge component PRs independently.
9. Tonal updates `TONAL.json`, `tonal.lock` and compatibility evidence to the exact merged commit SHAs.
10. Only after Tonal verification may the composed pair advance beyond PROPOSED/VERIFIED toward a separate SUPPORTED decision.

## Hard anti-shortcut rules

Tonal must reject a composition claim when:

- the answering model receives the hidden source/oracle;
- carrier-local Rosetta mappings are smuggled into a supposedly universal external prompt;
- `FALSE_EXACT` is nonzero;
- the model-facing active interface exceeds the declared W gate;
- a compact answer hides undeclared global scanning without accounting;
- component branches are referenced instead of exact immutable commits;
- Tlaloc changes Origami semantics rather than merely learning how to follow them;
- Origami treats an unvalidated Tlaloc candidate as automatically promoted.

## Current lock state

`tonal.lock` intentionally remains unchanged while this proposal is experimental. The current lock continues to describe the previously promoted component revisions. Feature-branch SHAs are evidence inputs, not release pins.
